# Lumavia Stone Website

**Version:** V1.0.2
**Status:** Development
**Brand:** Lumavia Stone
**Website:** lumaviastone.com

Lumavia Stone is an international stone products website focused on natural stone, garden products, architectural stonework, custom stonework, and overseas customer inquiries.

The website is built with Astro and designed as a lightweight, content-driven, SEO-friendly static website.

---

## 1. Project Overview

Lumavia Stone is being developed as a professional international stone brand and product presentation website.

The website is designed to support:

* Stone product presentation
* Brand building
* Overseas customer development
* Product inquiries
* SEO traffic acquisition
* Social media content
* Stone craftsmanship presentation
* Custom stone projects
* Future stone export business development

The website is **not** intended to be:

* A traditional Chinese stone factory website
* A low-price export website
* An Alibaba-style product catalogue
* A generic trading-company website
* A large collection of unverified products

The overall direction is:

> **Professional, minimal, credible, natural, and internationally oriented.**

## 6. Website Structure

The current primary navigation consists of:

* Home
* Catalogue
* About

The website does not use the following as independent top-level navigation items:

* Collections
* Craftsmanship
* Contact

### Home

Primary purposes:

* Establish the Lumavia Stone brand
* Present the visual identity
* Introduce key product categories
* Present stone and craftsmanship
* Direct users to the Catalogue
* Provide inquiry entry points

The Home page should not become an oversized product catalogue.

### Catalogue

Primary purposes:

* Present the product catalogue
* Allow category-based browsing
* Provide necessary filtering
* Lead users to product detail pages

Potential catalogue dimensions include:

* Category
* Material
* Featured

Actual filtering should follow the current product data and implementation rather than adding unnecessary functionality.

### Product Detail

Product detail pages belong to the Catalogue system.

A product page should help customers understand:

1. What the product is
2. What stone it uses
3. Product dimensions
4. Intended applications
5. Surface finish
6. Whether customization is available
7. Other relevant specifications
8. How to make an inquiry

The ultimate purpose is to help customers determine:

> Whether the product is suitable for their garden, landscape, architectural, or sourcing project.

### About

The About page may cover:

* Lumavia Stone
* Quyang stone-carving background
* Stone craftsmanship
* Product capabilities
* Customization capabilities
* International customer service

Craftsmanship-related brand content may be incorporated into About rather than maintained as a separate top-level page.

### Contact / Inquiry

There is no independent top-level Contact page in the current navigation.

Inquiry and contact functionality should be integrated into relevant pages, such as product pages or About, according to the actual implementation.

## 20. Code Modification Principles

When modifying code:

1. Read the existing code first.
2. Identify the actual root cause.
3. Make the smallest necessary change.
4. Preserve the existing architecture.
5. Avoid modifying unrelated files.
6. Do not add dependencies unnecessarily.
7. Check imports and exports.
8. Check Astro syntax.
9. Check TypeScript types.
10. Check image paths.
11. Check page routes.
12. Consider possible effects on other pages.

The preferred workflow is:

> **Understand → Diagnose → Implement → Verify**

rather than:

> **Guess → Modify → Break → Fix Again**

---

## 21. Bug-Fixing Principles

When an error occurs, first identify:

* Error message
* Error location
* Affected file
* Related data
* Type issues
* Imports / exports
* Props
* Routes
* File paths
* Astro syntax
* TypeScript
* CSS
* Build configuration
* Dependencies

Then provide:

1. Root Cause
2. Affected File
3. Problematic Code
4. Fix
5. Verification Method

Do not guess when the actual project files can provide the answer.

---

## 22. Code Output Rules

When the user requests:

**Complete code**

Provide a complete, directly replaceable file.

When the user requests:

**Modify this part**

Provide only the necessary modification.

When multiple files are involved, clearly separate them:

```text
File 1: src/pages/index.astro

File 2: src/components/ProductCard.astro

File 3: src/data/products.ts
```

Different files must not be mixed into one indistinguishable code block.
